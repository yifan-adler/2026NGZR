# 1.6.2 评分与执行审计

基线为工作区 `src1.6.1`。先只读检查该版本源码、测试工具及本机官方 SDK `/home/yifan/env-release-2026`，之后在独立 `src1.6.2` 修改。官方源码和评分规则未改。实际 SDK 哈希、构建命令和源码哈希随验证产物保存。

## 评分链路

官方：`Evaluate::cti_to_asp` 生成 `vtask.lp/vcons.lp`；成功的物理动作/Move 经 `evaluate.lp + forcons.lp` 产生下一状态，并由 `asp_to_state` 持久化状态与 `false(id,cons/ncons)`；结束时 `fortask.lp` 生成 `value(id,40/20)`，`EndEvaluation` 累加动作扣分和时间奖励。动作失败仍扣成本，但不持久化下一状态。AskLoc/Sense 不调用 `asp_to_state`。

内部：动作封装 `RecordAction` 收取实际发出的调用成本；成功动作更新 WorldState 和约束账本；`TerminalChecker` 读取当前目标真值与历史账本；`ScoreEvaluator` 给出基础分下界及可能分上界；`CandidatePlan` 用前后快照评估任务组，guarded 校验授权动作、前置状态、约束损失和最终结果。

| 问题 | 1.6.1 行为 | 官方语义与 1.6.2 修复 |
|---|---|---|
| 多绑定目标 | 评分使用规划器绑定，并对列表取全称满足 | 官方用 `1{task(id,...):cond}1` 选择一个绑定，读取第一个 answer set。评分独立枚举现有条件的所有匹配对象；全部一致时确定，混合结果为 UNKNOWN。规划器仍保留原绑定选择。 |
| 多绑定否定约束 | 先合并真值，再整体否定；且通常只看首个对象 | 官方约束展开所有绑定；任一违规即整条失分。逐绑定取反后合并。 |
| cons(task) | 作为动作禁令匹配实际命令，通常只看 X[0]/Y[0] | 官方检查动作之后的目标谓词。例如移动一个已在手上的 cup，也会违反禁 pickup。改为状态谓词并记录永久损失。 |
| 初始化约束检查 | 初始违反就清除资格 | 官方初始化不检查，首个成功状态改变才检查。初始化账本只建立资格。 |
| 约束计分 | 历史资格之外，还要求当前谓词满足 | 官方只检查持久化的 false；当前状态不能恢复失分，也不能额外取消尚未被检查的约束分。计分读取账本；当前谓词单独保留。 |
| Sense 更新 | 感知后更新约束失效账本 | 官方 Sense/AskLoc 的 ASP 结果不写回状态。内部观测不造成新的永久失分。 |
| UNKNOWN 历史 | 未见违规就继续确定计分 | 成功状态改变时的未知约束真值保留为历史不确定性，后续真值恢复不能证明之前没违规。下界不给这些约束分，上界保留可能分。 |
| putdown | 要求无 inside，且已知 location | 官方只有 outagent，即不在手和托盘。删除额外条件。 |
| puton/give、on | 对 inside 和持有状态施加同一套限制 | puton/give 要求同地且 outagent，不额外检查 inside；info(on) 只要求同地，持有物也可满足。 |
| inside 与 at | 容器位置传播给物体并用于计分；PutIn 后继续保留 planner location | 官方不由 inside 推导 at，PutIn 删除当前 at。Stage 1 单独保存评分用 at，不改变规划器定位方式。 |
| 失效约束推导 | Stage 2 约束已失分，相关 CONSTRAINT_DERIVED 仍可确定计分 | 相关约束失效或历史不确定时，其推导不能证明目标；评分改为 UNKNOWN。直接 Sense/动作证据仍有效。 |
| AskLoc 成本 | 内部 C++ 是 2；多个测试工具却算 1 | 修复 4 个版本内工具，只给 Sense 算 1；修正无目标时约束不计分的回归工具公式。 |
| 合成候选 | 删除临时目标后只重算确定分，可能分仍含临时目标 | 同步重算可能分；实际误差记录增加 goal_loss。 |

基础分为 `40 * goals + (goals > 0 ? 20 * credited_constraints : 0) - action_cost`。Move=4，AskLoc/物理动作=2，Sense=1。官方时间奖励为 `2 * int((5-time)*10)`，不参与内部确定性预测。测试读取原始官方分，不使用 1000 分封顶值作为计分依据。

## guarded / task-group 闭环

保留原开启条件、Stage 1 限制、25 ms 单次/100 ms 累计预算、beam/depth/branch 宽度、目标集合、期限预算、legacy 回退和默认关闭行为。没有引入新动作生成策略或 Stage 2 guarded。

1. 授权重投影除了动作和约束损失，还校验终态目标、已计分约束及基础分与搜索预测一致。
2. 真实任务组调用 `BeginCandidateExecution/EndCandidateExecution`；预测与实际动作数、成本、收益、失败原因进入原 DecisionFeedback，便于复核。
3. 授权组动作返回 false 时立即退出组，不继续发下一条授权动作。已发失败动作扣分一次；恢复从真实状态开始。
4. 终态额外核对实际累计动作成本和 credited 向量。投影保存/恢复新增账本、历史不确定性和评分位置事实，前置签名包含这些状态。
5. 只授权并执行原有任务组前缀；预测的 legacy tail 仍由原任务循环继续执行。阶段间出现新证据、动作失败或预算变化时不会承诺尾部预测。

## 保留差异

Stage 2 的初始误导、未知位置和历史未观测真值不能从内部状态还原官方真状态；基础分可能是保守下界。ASP 选择绑定、未支持的 condition/state 语法、官方首次 answer-set 顺序也不能由当前 C++ 表示完整复现。现有解析器对 `at`、`hold(0)`、`plate(0)` 约束、部分 color-only/size/动态条件的支持范围未扩展；不能宣称全语法等价。

Stage 1 的 at 事实已独立建账。Stage 2 仍使用证据系统，inside 的物理位置与官方显式 at 事实并未建立完整双状态模拟；无关容器缺少初始开关事实时，官方成功动作会补 closed，内部可能保持 UNKNOWN。未接入官方 ASP 为实时内部分数后端。

历史不确定性采用保守的整条约束标记。目标和约束 UNKNOWN 之间的联合关系未求解，possible_base_score 是宽松上界；守约/破约束门控可能因此改变原路径或漏掉收益。固定测试种子和所列回归不能证明所有题无降分。实际降分及未匹配案例见 RELEASE_1.6.2.md 和 summary.json。

本版本只有确定性规则、账本和现有有界搜索；没有贝叶斯模型、概率模型或学习策略。
